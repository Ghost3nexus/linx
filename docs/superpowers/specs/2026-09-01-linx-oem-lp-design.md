# LINX LP 全面刷新 — OEM/卸への転換 設計書

作成: 2026-09-01 (JST) / 承認: KOZUKI

## 1. なぜやるか

GMOインターネットから営業を受けた。広告も営業もしていないのにサービスを見つけられ、「WEBで戦いやすい商材」と評価された。提案は年 ¥1,144,000〜1,800,000。役務7つのうち、内部コーディング・構造化データ・llms.txt・メタ最適化・内部リンクは内製で当日できる。キーワード分析（ターゲット10＋ニーズ30）は提案資料としてすでに受領済み。

同時に、売り方を転換する。**店舗オーナー直販から、販売代理店とOSを持ちたい層（FC本部・チェーン本部）へのOEM卸へ。**

## 2. 転換の根拠

LINXの唯一の弱点は実績ゼロで、hacomono と正面から戦うとそこを突かれる。しかし**代理店とFC本部は「他にどこが使っているか」を聞かない**。見るのは利幅・自社ブランド化・データ帰属であり、「まだ誰も売っていない＝テリトリーが空いている」は売り文句になる。

型は確立している。海外では GoHighLevel（代理店に固定費、顧客数無制限、AI従量は実費＋マークアップで再課金）、日本では Reserve Kit（トライハッチ／東証プライム上場ベクトル子会社）が予約管理システムをOEM募集、使えるねっとがOEM約150社。さらに **Liny は Lステップへ OEM 提供していた実体**で、同じLINE領域でOEMは業界構造そのものだった。

## 3. 前提として確定していること

### 3.1 すでにホワイトラベルな部分（今日の事実）
`accounts` 軸の完全マルチテナントで、**アカウントごとに自前のLINEチャネル資格情報**を持つ。エンドユーザーが触るのは常に「その店の公式LINE」で、LINXの名前はどこにも出ない。AIの表示名も `bot_name` で変更可能。

### 3.2 まだ無い部分（LPで言い切ってはいけない）
1. 管理画面のブランディング（ロゴ・色・favicon の切替）
2. テナント別ドメイン／カスタムドメイン
3. **利用規約・プライバシーポリシーの出し分け** — OEM先が契約主体になるため法務上いちばん重く、最初の1社の前に必須
4. 代理店の階層（`accounts` の上にパートナー概念が無い）
5. 課金の分配（Stripe はアカウント→TP へ直課金）

### 3.3 料金構造（決定）
| | TP実費 | TP→代理店 | 代理店→エンド |
|---|---|---|---|
| 月額 | 約 ¥1,500〜2,500 | **¥5,000**（掛け率25%） | **¥19,800**（代理店が自由に決定） |
| AI応答 | ¥0.62/応答 | **¥1.3/応答**（実費の約2倍） | ¥3〜5/応答 または込みパッケージ |

大型・FC本部には固定枠型（月固定 ¥50,000 ＋ AI従量）を併用する。

AI従量は月額に丸めない。丸めるとTPに応答を削る動機が生まれる。上限到達時は **AI応答のみ止めて定型文に戻し、予約・会員・入退館・決済は止めない**（入退館が止まると店舗が営業できない）。

### 3.4 信頼の担保
実績の代わりに **動くものを触らせる**（実LINEデモ）。日本の代理店募集LPの定石にある「既存パートナーの声（写真付き）」の枠が空くので、そこに置く。

## 5. トップの構成（11ブロック）

1. **Hero** — 決定稿
   ```
   【初期費用0円／取り分 75%】
   御社の名前で売る、店舗のAIシステム。
   公式LINEに入るAIを、御社のブランドで。
   価格も契約期間も、御社が決められます。
   [ 卸値表を見る ]  [ 実際のLINEで試す ]
   ```
2. **2つの入口** — 販売代理店 / 自社のOSとして持ちたい層で分岐
3. **手に入るもの** — エンドが触るのは御社の公式LINE。LINXの名前は出ない（3.1の事実のみ）
4. **動くものを触らせる** — 実LINEデモ
5. **収益シミュレーター** — 顧客数と平均応答数を動かすと仕入れ・売上・粗利がその場で出る。損益分岐も自動表示
6. **どの業界に売れるか** — 業種別8ページへの導線＝市場証明
7. **まだ無いものを正直に書く** — 3.2 をロードマップとして明示
8. **テリトリー** — 地域・業種でパートナー数を制限（希少性と値崩れ防止を同時に）
9. **誰が作っているか** — TP会社情報・代表プロフィール（E-E-A-T）
10. **FAQ** — FAQPage 構造化データ付き
11. **CTA** — 資料請求／個別相談。フォームは複数箇所に置く（日本の代理店募集LPの定石）

## 6. 本番に出ている虚偽（Phase 1 で最優先に消す）

1. `src/app/layout.tsx` の JSON-LD に `aggregateRating 4.8 / reviewCount 12`。実績ゼロなので実在しない
2. `src/components/DataProof.tsx` の「唯一 LINE×AI自動応答を搭載したSaaS」。**2025年11月13日に LINEヤフー自身が月額¥3,000でAIチャットボット(β)を提供開始**したため成立しない

2 の差し替え方針：売る境界線を「AIが答える」から **「AIが予約を取り、会員を管理し、鍵を開ける」** に移す。LINEヤフーのAIは登録Q&Aから返すだけで、予約確定・会員管理・決済・入退館の業務連携が無く、グループトークでも使えない。

## 7. AI対策（GEO/AEO）

最大の穴は `/solutions/*` の8ページすべてが `"use client"` の共通コンポーネント（`IndustryLP.tsx`）で描かれ、**ページ固有の `metadata` が1つも無い**こと。検索エンジンとAIから見て8枚とも同じタイトルになっている。

対応項目（GMOの「内部コーディング」7項目に対応）：
- 業種別8ページに固有の title / description / h1
- `llms.txt` の追加
- 構造化データ：FAQPage / Organization / BreadcrumbList / SoftwareApplication（rating無し）
- `sitemap.ts` の修正（`/solutions/salon` 欠落、新規ページ追加）
- alt属性・内部リンクの整備
- E-E-A-T（代表プロフィール・会社情報）
